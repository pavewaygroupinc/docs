Pursar uses API keys to authenticate requests. Your API keys carry significant privileges, so be sure to keep them confidential. Do not share your secret API keys in publicly accessible areas such as GitHub, client-side code, or front-end bundles.

## Key Types

Pursar provides distinct key types for server-side operations, client-side interactions, and webhook verification:

| Key Type | Prefix | Location | Safe for Client? | Usage |
| :--- | :--- | :--- | :--- | :--- |
| **Secret Key** | `sk_test_...` / `sk_live_...` | Server backend | **NO** (Never expose) | Full API access: charges, refunds, customers, transfers, payouts |
| **Publishable Key** | `pk_test_...` / `pk_live_...` | Mobile / Web client | **YES** | Client-side SDKs, tokenization, initiating frontend checkout |
| **Webhook Secret** | `whsec_...` | Server backend | **NO** | Validating HMAC SHA-256 signatures on inbound webhook events |

## Supported Authentication Methods

Pursar follows the **Stripe standard HTTP Basic Authentication** format, while also supporting Bearer tokens and custom header formats.

### Method 1: HTTP Basic Auth (Recommended & Stripe Standard)

Pass your secret API key as the Basic Auth username. You do not need to provide a password.

```bash
curl https://api.viarosandbox.com/v1/charges/mobile-money \
  -u sk_test_uLsofsae3tB9Izwgeuy0Mxbh4JIxUPSG: \
  -H "Content-Type: application/json" \
  -d '{
    "amount": 25000,
    "currency": "XAF",
    "phone": "+237671234567",
    "customer_name": "Amara Diallo",
    "customer_email": "amara@example.com",
    "description": "Invoice #104 License"
  }'
```

### Method 2: Bearer Token

You can also pass your API key as a Bearer token in the standard `Authorization` header:

```bash
curl https://api.viarosandbox.com/v1/payment_intents \
  -H "Authorization: Bearer sk_test_uLsofsae3tB9Izwgeuy0Mxbh4JIxUPSG" \
  -H "Content-Type: application/json" \
  -d '{
    "amount": 5000,
    "currency": "XAF",
    "payment_method_types": ["mobilemoneyxaf", "card"]
  }'
```

### Method 3: `x-api-key` Header

For API gateways or serverless runtimes where custom headers are preferred:

```http
x-api-key: sk_test_uLsofsae3tB9Izwgeuy0Mxbh4JIxUPSG
```

## Code Examples

<CodeGroup>
```python Python
import requests

api_key = "sk_test_uLsofsae3tB9Izwgeuy0Mxbh4JIxUPSG"
base_url = "https://api.viarosandbox.com/v1"

# Using standard HTTP Basic Auth (Stripe pattern)
response = requests.post(
    f"{base_url}/charges/mobile-money",
    auth=(api_key, ""),
    json={
        "amount": 25000,
        "currency": "XAF",
        "phone": "+237671234567",
        "customer_name": "Amara Diallo",
        "customer_email": "amara@example.com",
        "description": "Premium License #104"
    }
)

charge = response.json()
print("Transaction ID:", charge["data"]["id"])
```

## Idempotency Keys

To avoid double charges caused by network timeouts or retries, Pursar supports idempotency keys for all mutating endpoints (`POST`, `PUT`).

Attach an `Idempotency-Key` header with any unique string (e.g., a UUID v4):

```bash
curl https://api.viarosandbox.com/v1/payment_intents \
  -u sk_test_uLsofsae3tB9Izwgeuy0Mxbh4JIxUPSG: \
  -H "Idempotency-Key: e82f3a47-7922-4a0b-9df0-7d7213ff2e61" \
  -H "Content-Type: application/json" \
  -d '{ ... }'
```

If a connection drops during an API call, you can retry the request with the identical `Idempotency-Key` without risk of creating duplicate transactions or multiple charges.
