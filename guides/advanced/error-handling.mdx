description: "Understand Pursar's Stripe-standard error types, HTTP status codes, and recovery procedures."
---

Pursar uses standard HTTP response codes to indicate the outcome of an API request. Every error response includes a standardized, machine-readable JSON `error` object structured identically to Stripe's error specification.

---

## The Pursar Error Object

```json
{
  "error": {
    "type": "invalid_request_error",
    "code": "parameter_missing",
    "message": "Field required",
    "param": "customer_name",
    "request_id": "req_019318b2_8291"
  }
}
```

### Attributes

| Attribute | Type | Description |
| :--- | :--- | :--- |
| `type` | string | The category of error. One of `api_error`, `authentication_error`, `card_error`, `idempotency_error`, `invalid_request_error`, or `rate_limit_error`. |
| `code` | string | Short programmatic identifier for the error (e.g. `insufficient_funds`, `parameter_missing`). |
| `message` | string | Human-readable explanation of what went wrong. Safe for debugging and developer logging. |
| `param` | string | The specific request field that triggered the error (if applicable). |
| `request_id` | string | Unique trace identifier for the request. Share this with Pursar Support for instant log correlation. |

## HTTP Status Codes

| Code | Status | Meaning & Recommended Action |
| :--- | :--- | :--- |
| **`200 OK`** | Success | Request succeeded. |
| **`201 Created`** | Created | Resource successfully created (e.g. Checkout Session, Customer). |
| **`400 Bad Request`** | Bad Request | The request was unacceptable, often due to missing a required parameter. |
| **`401 Unauthorized`** | Unauthorized | No valid API key provided or API key revoked. |
| **`402 Payment Required`** | Payment Failed | The payment attempt was declined (e.g. insufficient funds or card declined). |
| **`403 Forbidden`** | Forbidden | The API key doesn't have permissions for the requested operation. |
| **`404 Not Found`** | Not Found | The requested resource doesn't exist. |
| **`409 Conflict`** | Conflict | Concurrent request collision with the same idempotency key or duplicate resource. |
| **`422 Unprocessable`** | Validation Error | Payload structure is syntactically valid JSON, but fields violate schema rules. |
| **`429 Too Many Requests`** | Rate Limited | Too many requests hit the API too quickly. Slow down using exponential backoff. |
| **`500, 502, 503, 504`** | Server Errors | Something went wrong on Pursar's end. Retry safely using an `Idempotency-Key`. |

## Common Error Codes Reference

### Payment & Mobile Money Errors

| Error Code | HTTP | Description & User Action |
| :--- | :--- | :--- |
| `card_declined` | 402 | The card was declined by the issuing bank. Ask customer for a different card. |
| `insufficient_funds` | 402 | The customer's mobile money wallet or card has insufficient balance. |
| `telecom_timeout` | 402 | The customer did not enter their Mobile Money PIN within the 45-second operator window. |
| `operator_down` | 502 | The telecom operator (MTN, Orange) is experiencing gateway downtime. Fallback to [Manual USSD](/guides/payments/manual-payments). |
| `expired_card` | 402 | The card's expiration date has passed. |
| `incorrect_cvc` | 402 | The card's security code is invalid. |

### Validation & Integration Errors

| Error Code | HTTP | Description & User Action |
| :--- | :--- | :--- |
| `parameter_missing` | 400 / 422 | A required parameter was omitted from the request body. |
| `parameter_invalid` | 400 / 422 | A parameter value is malformed (e.g. invalid phone number E.164 format). |
| `idempotency_key_in_use` | 409 | The `Idempotency-Key` was submitted with different payload parameters. |
| `resource_not_found` | 404 | The requested customer ID, session ID, or transaction ID does not exist. |
